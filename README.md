# Конструктор опросов — лабораторная №3

Вариант 19, продолжение лабораторной №2. Java 17+, Spring Boot, Spring Data JPA / Hibernate, PostgreSQL. Сохранены адреса и JSON REST API лабораторной №2. Данные хранятся в PostgreSQL.

## Запуск в Windows

PostgreSQL должен быть запущен на `localhost:5432`. Откройте PowerShell **в папке RBPO_Lab3.1**:

```powershell
./setup-db.ps1
```

## Предметная модель и API

| Сущность | Данные | Адрес |
| --- | --- | --- |
| Пользователь | Имя, email, время создания | `/api/users` |
| Опрос | Название, автор, сроки, статус | `/api/surveys` |
| Вопрос | Опрос, текст, обязательность, варианты | `/api/survey-questions` |
| Участие | Опрос, респондент, статус, время создания и отправки | `/api/survey-participations` |
| Ответ | Участие, вопрос, выбранное значение | `/api/survey-answers` |

Для каждого адреса доступны `GET`, `GET /{id}`, `POST`, `PATCH /{id}`, `DELETE /{id}`. Чтение и обновление — `200`, создание — `201` с `id`, удаление — `204`; нарушение бизнес-правил — `400`, отсутствующая запись — `404`, конфликт ограничений — `409`.

Пользователь связан с авторскими опросами и участиями. У опроса есть вопросы и участия, у участия — ответы. Варианты вопроса хранятся в `survey_question_options` с сохранением порядка.; JSON содержит идентификаторы связей: `authorId`, `surveyId`, `respondentId`, `participationId`, `questionId`.

## Пять бизнес-операций

Все вызываются методом `POST` без тела.

| Операция | Адрес | Условия и результат |
| --- | --- | --- |
| Публикация | `/api/surveys/{id}/publish` | Только `DRAFT`, минимум один вопрос и будущая дата окончания. Если начало не задано, используется время сервера. Статус — `ACTIVE`. |
| Отправка | `/api/survey-participations/{id}/submit` | Активный опрос в пределах сроков, участие `IN_PROGRESS`, заполнены обязательные вопросы. Статус — `SUBMITTED`, сервер записывает время отправки. |
| Повторное прохождение | `/api/survey-participations/{id}/restart` | Только отправленное участие, опрос ещё принимает ответы. Ответы удаляются, время отправки очищается, статус — `IN_PROGRESS`. |
| Закрытие | `/api/surveys/{id}/close` | Только `ACTIVE`. Опрос становится `CLOSED`, незавершённые участия — `CANCELED`. Отправленные ответы сохраняются. |
| Новый раунд | `/api/surveys/{id}/copy` | Только закрытый опрос. Создаётся новый `DRAFT` с копиями вопросов и вариантов, без сроков, участий и ответов. Ответ — `201`. |

Остальные операции возвращают `200`. Статусы нельзя произвольно менять через CRUD. Вопросы редактируются только в черновике; ответы — в незавершённом участии, пока активный опрос принимает ответы. Значение ответа должно входить в варианты вопроса, если они заданы; пустой список вариантов означает свободный текст.

Контроллеры обрабатывают HTTP, сервисы проверяют правила и выполняют операции в `@Transactional`, репозитории Spring Data JPA обращаются к БД. Ошибка откатывает всю транзакцию. Пессимистическая блокировка опроса согласует публикацию, изменение вопросов, отправку и закрытие. После ожидания блокировки состояние участия перечитывается.

## Права и SQL

`database/setup-role.sql` создаёт отдельную роль без прав суперпользователя, создания БД и ролей. Таблицами владеет `postgres`. `database/grants.sql` выдаёт приложению подключение, использование схемы, `SELECT/INSERT/UPDATE/DELETE` таблиц и доступ к последовательностям идентификаторов. Приложение не может создавать или удалять таблицы и выдавать права. Подготовка выполняется отдельно от REST API.

Данные запросов JPA передаются параметрами; пользовательский ввод не склеивается с SQL. Каскады удаления заданы в SQL-схеме и работают при удалении через pgAdmin. `schema.sql` и `data.sql` выполняются одной транзакцией при первоначальной подготовке. Данные старого файла H2 автоматически не переносятся; исходные файлы сохранены.
